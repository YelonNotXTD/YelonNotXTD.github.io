# chart_gif_maker（视频区间 → GIF）

把视频中的**一块画面** + **一段时间**导出成循环 GIF 的纯静态小工具。
整个流水线都在浏览器里完成：上传、取帧、裁剪缩放、GIF 编码都没有服务器参与，
**视频不会离开你的电脑**，可以直接放在 GitHub Pages 上使用。

## 功能

- 上传视频（点击或拖拽，不上传网络），立即预览，显示**分辨率、总时长、文件大小**
- 在预览画面上**拖拽框选**区域，或直接输入 **X1,Y1 / X2,Y2** 两组像素坐标（双向同步）
- 输入**起始 / 结束时间（分 + 秒）**，支持"取当前播放时间"与选区循环预览
- 指定**目标宽度或高度**之一，另一维按原比例自动换算，默认 **12fps** 循环 GIF
- 生成结果直接预览 + 下载，并显示**帧数、实际时长、文件大小、耗时**
- 超出上限时**自动等比缩小 / 截断时长**，并在界面上说明做了什么调整

## 部署

把 `chart_gif_maker/` 整个目录丢进任意静态站点即可（本仓库里它已经位于
`gadgets/chart_gif_maker/`，推送后访问 `https://<你的域名>/gadgets/chart_gif_maker/`）。
没有任何构建步骤，也没有依赖需要安装。

本地想直接预览时需要一个 http 服务（`fetch` 和 ES module 在 `file://` 下会被浏览器拦住）：

```bash
npx serve .          # 或者用 VS Code 的 Live Server 插件
```

## 使用步骤

1. 拖入或选择视频文件，确认分辨率与总时长
2. 在画面上拖拽框选要导出的区域（角落方块可微调，拖动矩形可整体移动），
   或直接在右侧输入 X1/Y1/X2/Y2
3. 填写起始/结束时间（分、秒），可点「取当前」用播放头位置；勾选「循环预览该区间」反复检查
4. 选择目标「宽度」或「高度」并填入像素值，下方会显示**实际输出尺寸、帧数、时长**
5. 点「生成 GIF」，预览满意后下载；生成过程中可以随时「取消」

## 配置文件

所有可调参数都在 [config/gif.json](config/gif.json)，改完刷新页面就生效，**不需要重新构建**：

```json
{
  "fps": 12,
  "maxWidth": 325,
  "maxHeight": 325,
  "maxDurationSeconds": 3.25,
  "maxFileSizeMB": 512,
  "minCropSize": 8,
  "maxColors": 256,
  "optimizeTransparency": true,
  "transparencyThreshold": 0.8
}
```

| 字段 | 作用 |
| --- | --- |
| `fps` | 输出帧率，默认 12（改 24 会明显增大体积） |
| `maxWidth` / `maxHeight` | 输出尺寸上限方框（默认 325×325） |
| `maxDurationSeconds` | 输出时长上限（默认 3.25 秒） |
| `maxFileSizeMB` | 允许选择的视频文件大小上限 |
| `minCropSize` | 框选区域的最小边长（像素） |
| `maxColors` | 每帧最多颜色数，最大 256 |
| `optimizeTransparency` | 画面变化不大时只编码变化像素（大幅减小体积） |
| `transparencyThreshold` | 变化像素占比低于该值就启用上面的优化 |

越界时的处理（同样写在界面上提示用户）：

| 情况 | 行为 |
| --- | --- |
| 目标尺寸超过上限方框 | 等比缩小到刚好放进 `maxWidth×maxHeight` |
| 时间区间超过上限 | 从起始时间开始截断到 `maxDurationSeconds` |
| 时间区间超出视频长度 | 收敛到 `[0, 时长]` |
| 裁剪区域越界 / 过小 | 收敛到画面内，并保证不小于 `minCropSize` |
| 选择的文件超过 `maxFileSizeMB` | 直接提示，不读取 |

> 说明：这是纯静态站点，配置文件是普通可下载文件，所以这些上限只能当作
> **给不熟悉参数的用户兜底**，不能当作强制性校验——真正的强制校验必须有服务端。
> 想去掉界面上的上限提示，删掉 `app.js` 里给 `el.limitInfo` 赋值的那一行即可，限制依然生效。

## 实现要点

- **取帧**：从起点开始**顺序播放选区**，在 `requestVideoFrameCallback` 的每帧回调里同步抓像素，
  按"目标时刻落在前后两帧中点的哪一侧"决定采哪一帧（也就是预览暂停时看到的那一帧）。
  每帧只解码一次，耗时约等于"选区时长 + 编码时间"，**与视频 GOP 长短无关**：实测 1080p
  素材取 3.25s / 39 帧约 5 秒，而同样内容用逐帧 seek 会因从关键帧反复重解码慢到 20 秒
  （GOP 越长越慢）。`requestVideoFrameCallback` 不可用、标签页被切到后台导致播放停顿时，
  会自动回退到 `currentTime` 逐帧 seek 把缺的帧补齐。
- **缩放**：优先用 `createImageBitmap` 的 `resizeQuality:'high'` 一步完成"裁剪 + 高质量缩放"，
  回退到 canvas `drawImage`
- **静音**：视频元素默认静音，避免浏览器的自动播放策略挡住取帧需要的播放
- **调色板**：一帧里不同颜色不超过上限时走**精确调色板**（无损、体积最小，图表和界面截图几乎都命中）；
  超过时才交给 gifenc 的 PNN 量化器
- **透明差量**：和上一帧相比变化像素很少时，只写入变化像素，其余用透明像素透过上一帧显示
- **静止帧合并**：连续完全相同的帧合并进前一帧的显示时长，时间轴不变、体积大幅缩小
- **帧率**：GIF 的帧间隔只有 1/100 秒精度，逐帧四舍五入会让 12fps 变成 12.5fps；
  这里用累计取整（8、9、8、8、9…厘秒交替）保证平均帧率准确
- **颜色深度**：按调色板实际长度写入 `colorDepth`，小调色板用更短的 LZW 码，进一步省体积

## 浏览器要求

面向桌面版 Chrome / Edge（近两年的版本）。要求 `createImageBitmap`、`Blob`、
ES module 等基础能力；Safari 与 Firefox 的较新版本同样可用，但大文件与高分辨率下表现不如 Chrome。

能处理的格式取决于浏览器自身的解码能力：mp4/H.264、webm/VP8-VP9 通常没问题；
MKV、ProRes、部分 HEVC 等浏览器放不出来的文件会在预览阶段直接报错，需要先转码。

## 已知限制

- 起止时间是**按帧率均匀采样**，不做帧精确对齐；采样点正好落在源帧边界上时可能取到相邻一帧
- 生成耗时 ≈ 选区时长 + 1~2 秒编码；上限调大（时长、尺寸、帧率）后耗时会线性增长，
  1080p、325px、12fps、39 帧约 5 秒（生成期间请勿切走标签页，否则会退回逐帧 seek 变慢）
- 每帧最多 256 色，照片类内容会有可见的色彩损失（图表 / 界面截图基本无损）
- 生成时预览会静音播放一遍选区（这是取帧方式决定的，不是 bug）
- `file://` 直接双击打开无法工作（浏览器禁止本地 `fetch` 与模块加载），请用 http 服务或线上地址
- 没有服务端，因此没有"强制限制"，也没有任何上传体积/带宽保护——好处是隐私与零运维
